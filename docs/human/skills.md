## Overview

The skills concept covers the operational playbooks behind z-harness slash commands. Each `skills/<name>/SKILL.md` file (and several `commands/*.md` files that define full pipelines) specifies a command's phases, telemetry, user gates, subagent dispatches, output artifacts, and hard safety rules. These files are the practical source of truth for how planning, terrain mapping, deep research synthesis, debugging, implementation orchestration, test-case planning, final review, docs maintenance, memory authoring, statistics reporting, self-update, bulk quality uplift, targeted component auditing, fast-path bug fixing, plan-correctness auditing, plan-style auditing, and skill-file patching should run.

The skill family shares a route-policy model: planning and execution skills collect deterministic signals, call the advisory `planning-router` only when signals conflict, write `route-decision.md`, emit `plan_route_decision`, present an AskUser handoff gate, and stop rather than auto-running the next command. Skills reference stable provider-registry agent roles (`consultant-primary`, `consultant-secondary`, `reviewer`) and shared scripts for path resolution and logging. Skills that produce PushNotifications gate every call through `config.py should-notify --event <type>` (returns `yes`/`no`); notification policy and other runtime knobs are documented in `docs/human/config.md`. Skills with an explicit Setup block run `eval "$(config.py export-env)"` early to populate all `Z_HARNESS_*` env vars from config — `z-do` and `z-plan` are the two current adopters. Four skills have auto memory-review phases: `z-implement-all` (Phase 9), `z-review-all` (Phase 7), `z-debug` (Phase 10 — shipped branch only), and `z-suggest-memory` (sole memory authoring path, supports `--from-candidate-json` for review-agent output). All memory-review phases share a common pattern: `run-memory-review.sh` gates dispatch, the skip path emits `memory_review_terminal` via the helper, the ready path dispatches a `review-agent` subagent, and the terminal `memory_review_terminal` event (with `state: needs_user` or `ran_empty`) is emitted once per invocation. Push-notify for broken-context skip reasons uses a per-session dedup file (`.notify-dedup-session`) to suppress duplicate notifications.

Six skills carry the slug-confirm preference resolver retrofit: `z-plan`, `z-fix`, `z-debug`, `z-brainstorm`, `z-map`, and `z-plan-light`. The pattern is: hard unconditional slug-dir collision check first, then a soft non-obvious-slug confirmation gate via `python3 scripts/config.py resolve-question workflow.slug_confirm`. The resolver returns `skip` (silently accept, emit `askuser_skipped`), `prefill` (pre-select in AskUserQuestion with a preference label), `ask` (normal prompt; if `source == "conflict"`, surface the conflict details and offer a one-shot follow-up to record the user's answer as the new preference), or `halt` (emit a skill-specific halt event — e.g. `brainstorm_halt`, `debug_halt`, `light_halt`, `map_halt` — and exit cleanly without invoking `AskUserQuestion`; applies when `Z_HARNESS_NO_ASK=halt` is active and the resolver's no-ask gate returns `halt`). The `halt` result is a hard exit path: no AskUserQuestion is called, the run emits its skill-specific halt event, and control returns to the user. `config.py` also emits `askuser_resolved` events each time a question is resolved. `z-stats` Phase 4c reads these `askuser_resolved` events to show preference resolution statistics and conflict rate across the last 10 runs. `z-suggest-memory` gained a new `--kind routing-preference` mode that writes structured routing-preference memory entries to `docs/llm/workflow.json` (global) or `docs/llm/workflow-<project-slug>.json` (project scope), bypassing normal interactive collection. Its Phase 3a also gained a routing-flavored text detection gate: if candidate text matches `(always|usually|every time).*(after|before|when)`, the skill offers three branches — write to config.toml (yes-config), write as a routing-preference memory, or continue as a lesson-learned memory. `z-review-all` Phase 3.7 now runs a two-stage gate: a no-ask check (`config.py check-no-ask --question-id workflow.review_all_proceed`) fires first; if it returns `halt`, Phase 3.7 writes a partial `.review_state.json` (with `halted: true, halt_reason: no_ask_blocked`) and exits without calling AskUserQuestion. The Pre-Phase 0 resume check recognizes this halted-state file, emits `review_resume_from_halt`, deletes the file, and proceeds to a full Phase 0 re-run.

## Key entry points

- `skills/z-amend/SKILL.md:1` — `z-amend` — Amends SPEC/PLAN/TASKS or FIX.md artifacts while preserving completed-task state; changed task blocks get complexity re-classified.
- `skills/z-audit-plan/SKILL.md:1` — `z-audit-plan` — Read-only audit of existing plan artifacts; verifies references/design, runs adversarial consultants, and routes contextually when no plan, plan changes, or doc drift blocks confidence.
- `skills/z-brainstorm/SKILL.md:1` — `z-brainstorm` — Cheap pre-plan ideation with three vendor-diverse ideators, mandatory anti-bias checks, and BRAINSTORM.md output. Carries the slug-confirm preference resolver: hard collision check unconditionally, then soft `resolve-question workflow.slug_confirm` gate with skip/prefill/ask/conflict branching, plus `halt` result (emits `brainstorm_halt` event and exits without AskUserQuestion).
- `skills/z-debug/SKILL.md:1` — `z-debug` — Heavy unknown-root-cause debugging flow with a wrong-tool gate (Phase 0), conditional bisect fast-path (Phase 2.5 via `bisect-isolator` Haiku subagent), hypothesis rounds (3a round-1 + 3b adversarial), posterior scoring table, fix-gate (posterior == very_high + zero unexplained evidence), verification, optional MR-style review on the fix diff, mandatory post-mortem, and Phase 10 auto memory-review on the shipped branch only. Carries the slug-confirm preference resolver in Setup, including `halt` result (emits `debug_halt` event and exits cleanly). Phase 10 clears `.notify-dedup-session` unconditionally before the shipped/abandoned branch split.
- `commands/z-audit.md:1` — `z-audit` — Read-only structured audit pipeline for a target component; spawns one `auditor` subagent per selected dimension in parallel, runs bundled Gemini + Codex consult on merged findings, and emits REPORT.md plus TASKS.md (in `/z-implement-all`-compatible format) under `$Z_HARNESS_PLAN_DIR-audit/`. Auto-bails to escalation.md at >30 findings or >10 CRITICAL/HIGH.
- `commands/z-fix.md:1` — `z-fix` — Fast-path fix for bugs with a known diagnosis; Phase 0 wrong-tool gate (redirects to `/z-debug` if no hypothesis), premise check, doc-fetcher grounding, single bundled `light-fix` consult, inline implementation, non-negotiable Codex review, optional post-mortem. Auto-bails at >5 candidate files or cross-module impact. Carries the slug-confirm preference resolver in Setup.
- `commands/z-skill-fix.md:1` — `z-skill-fix` — Meta-skill for patching misleading skill/command/agent files; writes a diagnosis note in chat before editing, applies the smallest correct change, checks referrer consistency on deletions, re-reads for internal contradiction, and runs a mandatory Codex reviewer safety gate. Never auto-commits.
- `skills/z-do/SKILL.md:1` — `z-do` — Plan-less small-task runner; runs `config.py export-env` at Setup step 6; gates all PushNotifications via `config.py should-notify --event <type>`; doc-fetcher grounding (skipped when `$Z_HARNESS_DOCS_ALWAYS_APPLY=never`); inline implementation; mandatory reviewer gate; route handoff when scope grows.
- `skills/z-implement-all/SKILL.md:1` — `z-implement-all` — Full task-queue orchestrator with `--tasks` fast path for promoted artifacts, tree-rooted MANIFEST/SHARED-CONCERNS gates, spec-precheck, implementer/reviewer batching, hard caps, compaction breakpoints, and Phase 9 auto memory-review after Finalize. Notification policy via `docs/human/config.md`. Emits `memory_review_terminal` with `state: needs_user` or `ran_empty`; broken-context skip notifications are deduped via `.notify-dedup-session`.
- `skills/z-implement-next/SKILL.md:1` — `z-implement-next` — Single-task implementation with model selection from `**Complexity:**` stamp; reviewer gate; no auto-retry (re-invoke or use `/z-implement-all` for retry loop).
- `skills/z-improve/SKILL.md:1` — `z-improve` — Post-run retro that reads events/artifacts, proposes up to five harness improvements, applies accepted edits, and invokes `/z-suggest-memory` with a concept_hints list derived from touched file paths.
- `skills/z-init-docs/SKILL.md:1` — `z-init-docs` — Bootstraps docs/human and docs/llm, initializes INDEX files, writes the controlled TAGS.txt seed, and regenerates MEMORIES-FLAT.md.
- `skills/z-maintain-docs/SKILL.md:1` — `z-maintain-docs` — Refreshes stale docs via doc-updater (always with `dedup_tags: true`), validates memory preservation, optionally audits proposals with a pre-audit compaction state file, surfaces stale memories and tag collisions, and regenerates MEMORIES-FLAT.md after writes.
- `skills/z-map/SKILL.md:1` — `z-map` — Terrain-mapping flow with cost gate (Phase 0), slug + artifact collision handling (Phase 0.5, after cost gate), `--slug` flag parsing, doc-fetcher-first scaffolding, up to three Explore calls tracked as dispatched vs succeeded, bundled cross-LLM critique, and a mandatory no-recommendation invariant. Carries the slug-confirm preference resolver in Phase 0.5 (after the cost gate), including `halt` result (emits `map_halt` event and exits cleanly). Produces MAP.md.
- `skills/z-plan-light/SKILL.md:1` — `z-plan-light` — Lightweight planner for small fixes; produces FIX.md, runs bundled consultant review, implements inline, and uses a mandatory reviewer gate. Carries the slug-confirm preference resolver in Setup (hard collision check first, then soft `resolve-question` gate), including `halt` result (emits `light_halt` event and exits cleanly).
- `skills/z-plan-split/SKILL.md:1` — `z-plan-split` — Splits large topics into 2-6 clusters, enforces slug safety, plans leaves in parallel, reconciles file overlap with path normalization and severity heuristics, writes MANIFEST.md plus SHARED-CONCERNS.md, and emits a strict early-exit telemetry contract for every exit path.
- `skills/z-plan/SKILL.md:1` — `z-plan` — Full rigorous planning flow; runs `config.py export-env` at Setup step 4a; gates PushNotifications via `config.py should-notify`; docs-freshness route gate; doc-fetcher/Explore grounding (Haiku by default; cap 3 Explores); decisions; bundled consult; SPEC/PLAN/TASKS; and parallel complexity-classifier dispatch.
- `skills/z-research/SKILL.md:1` — `z-research` — Meta-orchestrator: intelligent dispatch decision (Phase 0, user-driven; reads MAP_STATE + BRAINSTORM_STATE from slug dir), cost gate (Phase 0.5, always before Phase 1 dispatch), inline `/z-map` + `/z-brainstorm` sub-command dispatch with audit trail, adversarial synthesis panel (3 perspectives + `research-judge` Opus), 10-section RESEARCH.md with approach decision matrix. Cost 3–6M tokens.
- `skills/z-review-all/SKILL.md:1` — `z-review-all` — Final-gate review with Pre-Phase 0 resume check (`.review_state.json` fast-forward, including new `halted: no_ask_blocked` state handling), sanity checks, optional TESTS.md suite gate, Phase 3.7 two-stage compaction breakpoint (no-ask gate first via `check-no-ask`, then preference resolver; halt writes partial state file with `halted: true`), two-pronged consultant review (implementation faithfulness + spec correctness), REVIEW-TASKS promotion, and Phase 7 auto memory-review. Emits `memory_review_terminal`; clears `.notify-dedup-session` at Phase 0 start and again at Phase 7 start.
- `skills/z-stats/SKILL.md:1` — `z-stats` — Read-only shell/jq/awk diagnostic for progress, wall time, token estimates, halts, Phase 4b memory-review activity (reads both `review_agent_call` and `memory_review_terminal` events, with old-shape `phase_end` back-compat mapping), **Phase 4c preference resolutions** (reads `askuser_resolved` events — total, by result/source/question_id, conflict rate), stalls, version history, and next-command suggestions.
- `skills/z-suggest-memory/SKILL.md:1` — `z-suggest-memory` — Sole authoring path for `memories[]`; supports append/edit/delete, `--from-candidate-json` for review-agent output, validates memory schema, writes atomically, regenerates MEMORIES-FLAT.md, and optionally refreshes human docs. New `--kind routing-preference` mode writes structured routing-preference entries to `docs/llm/workflow[-.].json` (bypasses interactive collection, jumps Phase 0 → Phase 1 → RP-1..8 → Phase 4/5/6/7/8). Phase 3a routing-flavored text detection gate redirects to config.toml write, routing-preference memory, or lesson-learned memory based on user choice.
- `skills/z-test/SKILL.md:1` — `z-test` — Optional planning-time semantic test-case planner; risk-ranks tasks, drafts non-trivial test cases, runs cross-LLM consult (mode `test-cases`), writes TESTS.md, and cross-links TEST-NNN entries into TASKS.md so tests are implemented alongside production code.
- `skills/z-update/SKILL.md:1` — `z-update` — Updates the z-harness plugin; detects symlink (git pull) vs tarball (atomic swap) installs; emits `harness_updated` telemetry; reinstalls Codex plugin cache if applicable.
- `skills/z-uplift/SKILL.md:1` — `z-uplift` — Bulk codebase quality uplift: decomposes repo into components, runs a cross-cutting pass for global issues, dispatches per-component `auditor` subagents across correctness/cleanliness/design dimensions in parallel, and drives sequential implementation via `/z-implement-all --tasks=`. Triggers on "bulk codebase quality", "uplift the codebase", "audit the whole repo", "review every component".

## How it interacts with others

- `commands` — Commands are the user-facing surfaces that mirror or invoke these skill workflows. Route-policy changes must stay aligned between command markdown and skill markdown. Several commands (`z-audit.md`, `z-audit-plan-style.md`, `z-fix.md`, `z-skill-fix.md`) define their pipelines directly in `commands/` without a corresponding `SKILL.md` re-entry alias.
- `agents` — Skills define when to dispatch `doc-fetcher`, `doc-updater`, `planning-router`, `implementer`, `reviewer`, `consultant-primary`, `consultant-secondary`, `review-agent`, `complexity-classifier`, `auditor`, `bisect-isolator`, `plan-style-reviewer`, `scope-probe`, and other subagents, plus the exact prompt contracts those agents receive.
- `scripts` — Skills rely on `plan-path.sh`, `log-event.sh`, `log-phase.sh`, `version.sh`, `regenerate-memories-flat.py`, `run-memory-review.sh`, and `config.py` for path resolution, telemetry, version stamping, memory flat-file sync, memory-review orchestration, and config-env export. `config.py resolve-question`, `config.py check-no-ask`, and the `askuser_resolved` / `askuser_skipped` event contract underpin the slug-confirm preference resolver and no-ask gate across multiple skills.
- `multi-ide-exports` — Export pipelines consume these skill files to generate Cursor rules, Codex prompts/skills, and Antigravity skills/workflows, so source skill edits must propagate through exported surfaces.
- `providers-registry` — Skills refer to stable agent roles (`consultant-primary`, `consultant-secondary`, `reviewer`) while provider resolution happens behind those roles.

## Edge cases / gotchas

- Route handoffs are not command chaining. Skills write a route decision, emit telemetry, ask the user, and stop after presenting the next command.
- The `planning-router` is advisory only. Deterministic thresholds win, malformed output falls back to deterministic routing or AskUser, and loop-prevention blocks ping-pong route chains capped at two entries.
- `/z-audit-plan` is only valid when plan artifacts exist. If none are found, it writes a no-plan route decision toward `/z-plan` instead of fabricating an audit.
- `/z-audit-plan-style` requires STYLE.md at the repo root. There is no `--no-style` escape — missing STYLE.md causes an immediate hard exit recommending `/z-style-init`. This differs from `/z-uplift`, which accepts `--no-style` for a degraded run.
- `/z-do` may not route directly to `/z-plan-split`; larger work routes through `/z-plan`, `/z-plan-light`, `/z-research`, `/z-brainstorm`, `/z-fix`, or `/z-debug` based on signals. Doc-fetcher dispatch in `/z-do` is skipped entirely when `$Z_HARNESS_DOCS_ALWAYS_APPLY=never` (set via config knob).
- `/z-plan-split` keeps `cluster_id` (e.g. `C1`, `C2`) separate from `cluster_slug` (the path segment). Swapping them breaks telemetry and on-disk layout. The `--clusters` flag supplies names only; scopes must still be derived per cluster.
- `/z-implement-all --tasks=<path>` bypasses normal slug/tree discovery and derives `$BASE` from the task file's parent directory; this is how promoted `REVIEW-TASKS.md` or `MR-REVIEW.md` queues are consumed.
- `/z-implement-next` is single-shot — no auto-retry on review failure. For retry, manually set the task stamp to `**Complexity:** high` and re-invoke, or use `/z-implement-all` which handles the retry loop.
- `/z-maintain-docs --audit` has a pre-audit compaction state file (`docs/llm/.maintain_docs_audit_state.json`); fast-forward is allowed only if the stale concept set is unchanged between invocations.
- `memories[]` are never authored by doc-updater. `/z-suggest-memory` is the only supported mutation path, and both stale-memory deletes and memory edits use atomic JSON writes.
- Phase 9 (`z-implement-all`) and Phase 7 (`z-review-all`) are soft phases: all failure paths are silent skips — no halt, no retry. They call `run-memory-review.sh` to gate whether a review-agent dispatch is warranted. Phase 10 (`z-debug`) follows the same pattern but only runs on the `status: shipped` branch — abandoned debug sessions emit no memory-review telemetry.
- `--from-candidate-json` in `z-suggest-memory` bypasses Phases 3a–3f; the candidate object must have `type` and `text` fields or the skill returns `STATUS: bad_input`. Pass `-` as path to read from stdin.
- Phase 4b in `z-stats` reads both `review_agent_call` events and `memory_review_terminal` events from metrics.jsonl, with a back-compat mapping from old `phase_end` shape; it is read-only and adds no writes.
- Phase 4c in `z-stats` reads `askuser_resolved` events to produce a preference resolutions summary (by result, source, question_id, and conflict rate). It is read-only. If no events are found, it prints a "none found" note and skips the conflict-rate line.
- `memory_review_terminal` is the canonical terminal event for all memory-review paths. It is emitted by `run-memory-review.sh` for all skip states, and by the orchestrating skill for `ran_empty` and `needs_user` states. `review_agent_failed` and `review_agent_malformed` are orthogonal failure-class events — they do NOT emit `memory_review_terminal`.
- Broken-context skip push-notifications (for `tags_missing`, `no_plan_dir`, `missing_args` reasons) use a per-session dedup file (`.notify-dedup-session`) keyed by `slug:reason`. The dedup file is cleared at the start of each fresh `/z-review-all` Phase 0 invocation; at the top of each fresh `/z-debug` Phase 10 (before the shipped/abandoned split); at the start of Phase 7 in `/z-review-all`; and before the first task dispatch in `/z-implement-all`.
- The slug-confirm preference resolver in `z-brainstorm`, `z-map`, `z-plan-light`, `z-debug`, and `z-fix` (Setup) now has four result values: `skip`, `prefill`, `ask`, and `halt`. The `halt` result fires when `Z_HARNESS_NO_ASK=halt` is active and the `check-no-ask` gate returns `halt` for the slug-confirm question. Each skill emits its own halt event (`brainstorm_halt`, `debug_halt`, `light_halt`, `map_halt`) and exits without invoking AskUserQuestion. The hard unconditional slug-dir collision check runs before the resolver and is never bypassed by resolver outcome.
- `/z-review-all` Phase 3.7 compaction breakpoint now runs a two-stage gate: (1) `config.py check-no-ask --question-id workflow.review_all_proceed` fires first — if it returns `halt`, Phase 3.7 writes a partial `.review_state.json` with `halted: true, halt_reason: no_ask_blocked` and exits without calling AskUserQuestion; (2) if the no-ask gate returns `proceed`, the full `resolve-question workflow.review_all_proceed` resolver runs for skip/prefill/ask. On the next `/z-review-all` invocation after a `halt`, the Pre-Phase 0 resume check detects the halted-state file, emits `review_resume_from_halt`, deletes the file, and runs a full Phase 0 re-run.
- `z-suggest-memory --kind routing-preference` writes to `docs/llm/workflow.json` (global scope) or `docs/llm/workflow-<project-slug>.json` (project scope). If the target file does not exist, it is created as a minimal stub and registered in INDEX.json. Mutually exclusive with `--edit`, `--delete`, and `--from-candidate-json`.
- `z-suggest-memory` Phase 3a routing-flavored text detection only fires when candidate text is already available AND has no explicit type set. If the detection pattern matches, the user chooses: yes-config (writes to `.z-harness/config.toml` via `config.py set` — not yet shipped as of this writing), write-as-routing-preference (redirects to RP flow), or write-as-lesson-learned (continues silently). No detection → Phase 3b proceeds without interruption.
- Adding a tag alias records TAGS.txt only; memory tags collapse on a later run when doc-updater's step 3.5 reads the updated TAGS.txt.
- MEMORIES-FLAT.md regen is mandatory after doc writes or memory mutations.
- `/z-debug` Phase 2.5 bisect is a conditional fast-path, not a required phase. It fires only when the bug is a regression with a known-good baseline and a scriptable repro. `refused`, `failed`, and `bisect_unusable` returns all fall through to Phase 3a unchanged — bisect never blocks the pipeline.
- `/z-debug` bisect offending SHA does not pre-fill the winning hypothesis; it augments the Evidence Inventory and seeds Phase 3a prompts. The fix-gate still requires `posterior == very_high` and zero unexplained evidence rows.
- `/z-debug` auto-bail thresholds no longer include `>5 files` as a trigger; only cross-module impact, architectural change, or new public surface trigger escalation. The hard cycle cap is 5 (halt when cycle 6 would be needed); soft warning fires at cycle 3.
- `/z-fix` Phase 0 is non-skippable even if the user passed an argument. A symptom description alone is not a hypothesis — if the user cannot name a cause, the command exits with a `/z-debug` recommendation.
- `/z-fix` auto-bail threshold is >5 candidate files, >2 non-obvious decisions, or cross-module/cross-crate impact. The hard inline implementation limit is 7 files regardless of what FIX.md anticipated.
- `/z-fix` does not auto-trigger MR-review; run `/z-mr-review` separately if needed.
- `/z-audit` auto-bail thresholds are >30 total findings or >10 CRITICAL/HIGH findings after Phase 4 consult. On bail, an `escalation.md` is written and TASKS.md is not generated.
- `/z-audit` produces a minimal SPEC.md and PLAN.md alongside TASKS.md so `/z-implement-all` can resolve context even though no full planning flow ran.
- `/z-skill-fix` only patches skill/command/agent files. Bugs in repo code route to `/z-plan-light`; missing project conventions route to CLAUDE.md or a memory entry; policy disputes are not defects and should not weaken gates.
- Before recommending any `git reset --hard HEAD~N`, `git commit --amend`, or interactive-rebase squash on a branch tracking an upstream, run `git branch -r --contains <sha>`. If the upstream ref appears, STOP and recommend rebase or new-commit instead.
- `/z-review-all` Pre-Phase 0 deletes a stale `.review_state.json` and starts fresh if HEAD has changed or artifact files are missing; if the file is corrupt (bad JSON, missing fields), it also deletes and restarts. A `halted: true, halt_reason: no_ask_blocked` state file is treated specially: the Pre-Phase 0 check emits `review_resume_from_halt`, deletes the file, and proceeds to a full re-run (not a fast-forward).
- `/z-plan` Phase 8 dispatches one `complexity-classifier` (Haiku) per task in parallel after all task blocks are written; the classifier returns `REASON: user-authored override` and leaves existing stamps alone if the user pre-authored a `**Complexity:**` line.
- `/z-map` strips `--slug=<value>` from `$ARGUMENTS` before computing `input_hash`; the cleaned question plus remaining flags are what get canonicalized. `/z-research` does the same — the `--slug=` token must not appear in any prompt to subagents.
- `/z-research` Phase 0 (dispatch decision) runs before Phase 0.5 (cost gate). The cost gate always runs before Phase 1 sub-command dispatch. At least one sub-command must succeed before launching the synthesis panel; the synthesis panel requires all 3 perspectives to succeed before calling `research-judge`.
- `/z-test` cross-task tests (entries with `task: null`) are not linked into TASKS.md; they are deferred to `/z-review-all` or standalone follow-up tasks. The cross-LLM consult step is non-skippable.
- `/z-update` in tarball mode halts if `Z_HARNESS_RELEASE_URL` still points at `example.com`. Symlink mode aborts on dirty plugin tree.
- `/z-uplift` requires `STYLE.md` at the repo root; if missing it halts and recommends `/z-style-init`. Pass `--no-style` to proceed with a degraded generic rubric. The `perf` dimension is excluded from default dimensions to bound cost; add it explicitly via `--dimensions=correctness,cleanliness,design,perf`.
- `/z-uplift` MANIFEST.md is the single resume authority; all state transitions are atomic via tmp-then-rename writes. Slug collision detection on component names requires resolution via AskUserQuestion before COMPONENTS.md is written.
- `config.py export-env` populates all `Z_HARNESS_*` env vars from the project config at startup (currently used in `z-do` Setup step 6 and `z-plan` Setup step 4a). Skills that do not yet call `export-env` must not assume `Z_HARNESS_NOTIFY` is set; they reference the `docs/human/config.md` pointer and use `Z_HARNESS_NOTIFY_LEVEL` with a default fallback.
- All PushNotification calls in skills that use `config.py` are gated by `config.py should-notify --event <type>` returning `yes`. Hard-pause notifications (compaction breakpoints, halt-on-skip-flagged) fire regardless of notify level and bypass the should-notify check.

## Examples

- To understand a route bailout from light mode, read `skills/z-plan-light/SKILL.md` Plan Route Check and Phase 1. The artifact to inspect is the run's `route-decision.md`.
- To debug why tree-rooted implementation refused to start, read `skills/z-implement-all/SKILL.md` Setup 2b for MANIFEST, SHARED-CONCERNS, partial-tree, and ack validation gates.
- To add a durable lesson after a debug or retro run, use `/z-suggest-memory`; do not edit `memories[]` directly and do not ask doc-updater to invent memory entries.
- To pipe a review-agent candidate directly into memory, run `/z-suggest-memory --concept <slug> --from-candidate-json <path> --source "incident:<run-id>"`.
- To record a routing preference (e.g. always confirm slug), run `/z-suggest-memory --kind routing-preference --question-id workflow.slug_confirm --value prefill --strength strong --scope global`.
- To see how many memory candidates the last implement-all run surfaced and how many were accepted, run `/z-stats` and check the Phase 4b output — it shows `review_agent_call` counts and `memory_review_terminal` state aggregations for the last 10 runs across all parent commands.
- To see how often slug-confirm prompts were skipped or prefilled by a stored preference, run `/z-stats` and check the Phase 4c "Preference resolutions" section — it shows counts by result, source, question_id, and conflict rate.
- To resume a `/z-review-all` run that was interrupted after building the cumulative diff, re-invoke `/z-review-all`; if `.review_state.json` is valid and HEAD is unchanged, Phases 0–3.5 are skipped automatically.
- To consume a promoted REVIEW-TASKS.md queue without full plan discovery, run `/z-implement-all --tasks=z-harness/<slug>/REVIEW-TASKS.md`.
- To implement one task at a time (manual pacing), use `/z-implement-next`; it does not auto-advance and keeps each task in a fresh context.
- To plan semantic test cases before implementation, use `/z-test` after `/z-plan`; the TESTS.md it produces is consumed by `/z-implement-all` automatically.
- To run a full-codebase quality pass, use `/z-uplift`; for a single component only, use `/z-audit <target>`; for branch-diff review before merging, use `/z-mr-review`.
- To audit plan artifacts for style and quality issues before writing any code, use `/z-audit-plan-style`; findings are emitted as amendment-shaped blocks in `PLAN_STYLE_AUDIT.md` for direct promotion into `/z-amend`.
- To update the z-harness plugin itself, run `/z-update`; it detects symlink vs tarball and picks the safe update path automatically.
- To fix a bug when you already have a hypothesis, use `/z-fix`; if the root cause is unknown, use `/z-debug` instead (Phase 0 of both commands routes appropriately).
- To patch a skill or command file that misled during a run, use `/z-skill-fix`; it diagnoses the failure in chat, applies the smallest correct edit, and runs a Codex reviewer gate before returning control to the user.
- To inspect the notification policy or change it project-wide, read `docs/human/config.md`; the `notify.level` knob controls which events fire PushNotification calls.
