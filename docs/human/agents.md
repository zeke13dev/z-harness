## Overview

The agents concept covers the specialized subagent prompt files under `agents/`. Each file declares an isolated worker role through frontmatter (`name`, `description`, `tools`, `model`) and then defines the inputs, execution procedure, telemetry, and parseable return contract that the surrounding z-harness commands rely on. Agents are always spawned fresh per invocation; the orchestrating command owns all context, user interaction, artifact writes, and final routing decisions.

The suite is split by responsibility: planning route advice (`planning-router`, recently rewritten with exact-vs-historical artifact matching and a post-artifact recommendation gate), cluster planning (`cluster-planner`, now writes `INTENT.md` + `MANIFEST.json` instead of the legacy `SPEC.md`/`PLAN.md`/`TASKS.md` trio), complexity stamping (`complexity-classifier`), scope classification (`scope-probe`), file-scope extraction for the plan registry (`scope-extractor`), implementation (`implementer`, now routed through a native model-routing layer instead of a fixed frontmatter model), post-implementation correctness review (`reviewer`), self-review when `Z_HARNESS_CONSULT=off` (`self-reviewer`), code-quality review (`mr-reviewer`), plan artifact style review (`plan-style-reviewer`), fast first-pass pre-review (`pre-reviewer`), spec validation (`spec-precheck`), post-run memory candidate generation (`review-agent`), behavioral axiom mining (`axiom-extractor`), mechanical Tier 1 per-task doc sync (`tier1-doc-updater` — see gotcha below: currently has no live dispatcher), documentation refresh (`doc-fetcher`, `doc-updater`), external lookup (`external-lookup`), session handoff curation (`context-curator`, now tied to durable `/z-execute` settle points), remote verification (`remote-runner`, now with a memory-pressure preflight gate and coalesced BFS-level dispatch), regression bisect isolation (`bisect-isolator`), auditing (`auditor`), cross-LLM consultation (`consultant-primary`, `consultant-secondary`), fanout reconciliation (`scope-reconciler-audit`, `scope-reconciler-brainstorm`), wide-mode brainstorm framing clustering (`ideator-clusterer`), adversarial-panel final synthesis for `/z-research` (`research-judge`), and workflow question resolution (`resolver`). The three proxy agents (`consultant-primary`, `consultant-secondary`, `reviewer`) resolve provider CLIs at runtime through `scripts/resolve-provider.sh` and each declares an `expected_contract` that `resolve-persona.py validate` enforces when a persona is bound to the role.

**Not covered here:** the `intent-classifier` and `task-tree-generator` agents (planning-depth classification and BFS-level task generation for the Adaptive INTENT engine) still exist under `agents/` but are documented exclusively in the `adaptive-intent` concept — do not duplicate their contracts in this file. Four newer agents present in `agents/` (`artifact-scout`, `explore`, `report-synth`, `resume-cluster`) are also outside this concept's current source-file scope and are not yet covered by any concept doc; flagged in NOTES for the caller.

## How it interacts with others

- `commands` -- Commands are the orchestrators that decide when to spawn each agent, pass compact inputs, parse exact return shapes, and write user-facing artifacts. `/z-execute` dispatches `scope-extractor` at Phase 0 to seed the active-plan registry, then dispatches `self-reviewer` instead of `reviewer` when `Z_HARNESS_CONSULT=off`, and dispatches `axiom-extractor` in Phase 9 alongside `review-agent` when `AXIOM_READY` is signaled. `/z-plan-split` dispatches `cluster-planner` once per cluster (Phase 2), then reads each cluster's `MANIFEST.json` for reconciliation. `/z-audit-plan-style` dispatches `plan-style-reviewer` before any code is written. `/z-plan` dispatches `scope-extractor` after TASKS.md is finalized. `/z-brainstorm` dispatches `ideator-clusterer` after all wide-mode waves complete (WIDE_N > 3). `pre-reviewer` is dispatched by `/z-execute` and `/z-review-all` as an opt-in pre-review cycle (gated by `Z_HARNESS_PRE_REVIEW=1`). Note: `tier1-doc-updater` is defined but currently has no live dispatcher anywhere in `skills/` -- see Edge cases.
- `scripts` -- Agents call shared scripts for telemetry, provider resolution, timeout detection, plan path handling, remote sandbox sync, and memory review. `remote-runner` delegates all sandbox lifecycle to `scripts/remote-sandbox-sync.sh`, including the new `--sandbox-key` flag for coalesced level-boundary dispatch. The three proxy agents call `scripts/resolve-persona.py` indirectly via `scripts/resolve-provider.sh` to enforce `expected_contract` validation. `scripts/parse-followups-block.py` is the canonical parser for `reviewer`'s and `self-reviewer`'s `**FOLLOWUPS:**` blocks. The resolver is implemented in `scripts/config.py` (`cmd_resolve_question`). `scope-extractor`'s output is consumed by `scripts/active-plan-registry.py update-scope`. `tier1-doc-updater`'s staged output (when it eventually runs) is reconciled by `scripts/reconcile-tier1-staged.py`.
- `lookup-contract` -- `external-lookup` must follow the canonical envelope in `docs/llm/lookup-contract.json`; the JSON contract wins over inline prose if they diverge.
- `personas-and-roles` -- Each proxy agent (`consultant-primary`, `consultant-secondary`, `reviewer`, `self-reviewer`) declares an `expected_contract` field. `resolve-persona.py validate` hard-fails with an actionable message if a persona bound to a role declares a mismatched contract. `consultant-primary` and `consultant-secondary` require `contract: freeform`; `reviewer` and `self-reviewer` require `contract: review-verdict`.
- `active-plan-registry` -- `scope-extractor` seeds file-scope data into the registry via `scripts/active-plan-registry.py update-scope`; overlap detection in `/z-execute` and `/z-plan` depends on this seeding being present before the plan starts. `planning-router` now also consumes registry overlap (`active_registry_overlap`) and worktree overlap (`worktree_overlap`) signals when the caller supplies them.
- `axioms` -- `axiom-extractor` wraps `scripts/axiom-extract.py` and is dispatched post-run by `/z-execute`; its output feeds the `/z-axiom-scan` / `/z-axiom-approve` workflow.
- `session-handoff` -- `context-curator` folds z-harness run telemetry into bounded SESSION.md handoff artifacts at durable `/z-execute` settle points, preventing O(N^2) context growth across parallel task runs; it stays strictly separate from the live `/z-handoff` `SESSION_CONTEXT.md` artifact.
- `adaptive-intent` -- `implementer` and `reviewer` now read optional intent-conversation artifacts (`intent_flags_path`, `execution_strategy_path`, `workstreams_path`) produced by the Adaptive INTENT `/z-plan` pipeline. `cluster-planner`'s `INTENT.md` output mirrors the top-level INTENT contract shape. The `intent-classifier` and `task-tree-generator` agents that generate/classify the INTENT engine itself are documented in the `adaptive-intent` concept, not here.
- `z-brainstorm` -- `ideator-clusterer` is dispatched by `/z-brainstorm` for wide runs. `scope-reconciler-brainstorm` handles HEAVY-mode chunk reconciliation; these two agents serve distinct axes and must not be confused.

## Edge cases / gotchas

- `reviewer` and `self-reviewer` both emit a `**FOLLOWUPS:**` block (fenced JSON array) after `### Major`. Minors and nits MUST go here -- never silently dropped. The orchestrator parses via `scripts/parse-followups-block.py` and calls `scripts/sink-add.sh` per entry. Parse failure logs `followup_block_parse_failed` and never crashes the return path. Required per-entry fields: `priority`, `name`, `recommended_command`, `cited_paths`. Optional: `recommended_command_safe_to_retry` (default `false`), `auto_close_eligible` (default `false`; reviewer is on the producer-class allowlist and may set `true`).
- **DRIFT -- `tier1-doc-updater` has no live dispatcher.** No file under `skills/` (or anywhere else in the repo) contains `subagent_type="tier1-doc-updater"`. It was originally dispatched from the legacy `commands/z-implement-all.md` step 7a.5 (added in the same commit as the agent itself), but the dispatch call was already absent by the time the `z-implement-all` -> `z-execute` rename commit landed -- meaning it was silently dropped during an earlier restructuring of `z-execute`, not deliberately removed. `docs/human/tier1-doc-updater.md` (a separate concept doc, out of this refresh's scope) still asserts active per-task dispatch and is equally stale. Flagged for the caller to decide: restore the dispatch call, or retire the agent + its concept doc.
- `self-reviewer` is the fallback when `Z_HARNESS_CONSULT=off`. It is an Opus-model agent (not a proxy), so it calls no external CLI and has no `resolve-provider.sh` step. It still emits `review_start` / `review_end` telemetry in the same shape as `reviewer`.
- `scope-extractor` is best-effort and non-fatal: if the seeding call fails, `active-plan-registry.py` self-logs a `registry_error` and the implement-all run continues. The overlap detection in the same run may then miss some files from this plan, but other sessions' overlap checks will still work correctly.
- `axiom-extractor` proposes only -- the fenced JSON array it returns is NOT written to the axiom store automatically. No axiom is approved without a subsequent human `/z-axiom-approve` action.
- `resolver` result domain: `skip | prefill | ask | halt | defer-to-sink`. The `defer-to-sink` result means the orchestrator must NOT prompt the user -- it calls `scripts/sink-add.sh` with the question context as the entry body, logs `followup_deferred_from_resolver`, and proceeds. If `sink-add.sh` exits non-zero, the orchestrator falls back to `ask` -- the question cannot be silently dropped. No registered question currently maps to `defer-to-sink` (the former `/z-implement-next`-tied example was removed when that command was deleted); the result class remains available for a future `question_id`.
- `consultant-primary`, `consultant-secondary`, and `reviewer` are proxy prompts that shell out to provider CLIs resolved at runtime. Old hard-coded `codex-consultant.md`, `gemini-consultant.md`, and `codex-reviewer.md` references are stale.
- The proxy agents source `scripts/check-timeout.sh` so `$TIMEOUT_CMD` is available when GNU timeout or gtimeout exists, and they emit `consult_start` events before provider calls so liveness checks can see hangs.
- `consultant-primary`/`consultant-secondary` `plan-review` mode input shape changed: callers now pass `planning_mode` plus concrete artifact paths (`INTENT.md`+`TASKS.md` in intent mode, `SPEC.md`+`PLAN.md`+`TASKS.md` in full mode) rather than a fixed `SPEC.md`+`PLAN.md` pair. Their `light-fix` mode now serves `/z-fix` and `/z-debug` Phase 6 only -- `/z-plan-light` was deleted from the codebase entirely.
- **`planning-router` was substantially rewritten.** Primary route targets are now `/z-do`, `/z-plan`, `/z-plan-split`, `/z-brainstorm`, `/z-sharpen`. `/z-plan-light` no longer exists; `/z-map` is now a legacy compatibility wrapper that just delegates to `/z-explore --depth=deep` and is not itself a router target; `/z-research` is no longer reachable from planning-router (users invoke it directly). `terrain_uncertain` now returns `STATUS: ask_user` with `needs_terrain_grounding` rather than recommending `/z-map`. The deprecated `needs_research` alias also now resolves to `ask_user`, not a `/z-map` route.
- `planning-router` adds a hard **exact-vs-historical** distinction: only an exact finished plan (`artifact_exact_slug_match && artifact_finished_plan_match`, or the legacy `has_existing_plan` without contradictory artifact signals) unlocks `/z-amend` or `/z-audit-plan`. Historical-similar candidates (`artifact_similar_candidates` non-empty, or `artifact_match_basis` containing `historical_similar`) are warning-only (`existing_artifact_similar`) and must never unlock those contextual exits. `INTENT.md` + a canonical `TASKS.md` counts as a finished plan-family artifact set even without `SPEC.md`/`PLAN.md`.
- `planning-router` also gained **overlap signals**: a non-empty `active_registry_overlap` (and no post-artifact/exact-finished-plan rule already routed) returns `STATUS: ask_user` with `active_plan_overlap` -- active claims need arbitration before more planning. `worktree_overlap` alone is warning-only and must never by itself force `ask_user`.
- `planning-router` adds a **post-artifact recommendation gate** (`post_artifact_check: true`): after plan artifacts already exist, it can recommend `/z-plan-split` (too many tasks), `/z-sharpen` (question-heavy artifacts), or `/z-brainstorm` (unsettled approach) -- always surfaced through the caller's own route gate, never auto-dispatched.
- `planning-router`'s route-chain loop detection is now topic-scoped (matches on `from_command`+`to_command`+overlapping `reason_codes` for the same topic), not a flat 2-hop counter, so it can catch a sharpen<->plan ping-pong on the same topic that a simple hop count would miss.
- `doc-updater` is the structural refresh path, not the memory authoring path. It must copy `memories[]` exactly; `/z-suggest-memory` is the only intended authoring and editing path for memories. It must never edit `docs/llm/INDEX.json` directly; its LLM-tier JSON now carries a required concept-level `summary` field specifically so `/z-maintain-docs` can refresh INDEX.json metadata from that JSON.
- `remote-runner` delegates sandbox creation to `scripts/remote-sandbox-sync.sh`, which enforces: (1) SLUG and TASK_ID are validated against path-traversal patterns and TASK_ID cannot equal the literal string `base`; (2) the shared `<slug>/base/` is seeded once via an atomic `mkdir`-lock -- the winner rsync-seeds and writes a `.base-ready` marker, concurrent losers poll for that marker up to 600 s; (3) per-task overlays use `--link-dest=$BASE` for hard-linked unchanged files.
- `remote-runner` step 7 NEVER deletes `<slug>/base/` -- even on success. The warm base is long-lived and shared across all tasks in a slug. Only the per-task (or, when `sandbox_key` was passed, per-level) directory is removed on success.
- If a `remote-sandbox-sync.sh` invocation died between acquiring `.base.lock` and releasing it, the lock persists and all future seeding attempts timeout after 600 s. Recovery: `ssh <remote-host> 'rmdir ~/dev/qt-bot-sandbox/<slug>/.base.lock'`.
- **`remote-runner` gained a mandatory memory-pressure (PSI) preflight gate** before any `needs-sandbox` build/test. Rationale: `systemd-oomd` kills by user-slice memory PRESSURE, not per-unit caps or load -- on 2026-06-20 a confined build pushed `user@1000` PSI past the 50% threshold and oomd killed `qt-trading.service` at LOW load (3.2). The gate polls `MemAvailable`/`loadavg`/`/proc/pressure/memory` twice 10s apart, up to 15 attempts (~15 min), and if the box never clears, returns `STATUS: deferred` (reason `box_pressure`) instead of running the build. Thresholds: `Z_HARNESS_REMOTE_MIN_AVAIL_MB` (default 6000), `Z_HARNESS_REMOTE_MAX_LOAD` (default 14). Read-only queries and log tails skip this gate.
- `remote-runner`'s new `sandbox_key` (e.g. `<slug>/level-<N>`) is only for coalesced BFS-level-boundary dispatch under `/z-execute`'s INTENT scheduler; the shared warm base at `<slug>/base/` always stays keyed by `<slug>` alone regardless of `sandbox_key`.
- `bisect-isolator` applies a POSIX-ERE verb-grep to the caller-supplied repro command before touching the repo. macOS/BSD grep does not support Perl lookaheads, so refusal checks use split patterns + explicit shell conditionals. It also installs a `cleanup_bisect` trap to guarantee `git bisect reset` on all exit paths.
- `bisect-isolator` runs a mandatory sanity gate (step 4) that verifies the repro inverts across the range before starting bisect proper. If the repro passes on the bad ref or fails on the good ref, it returns `STATUS: bisect_unusable`.
- `plan-style-reviewer` reviews design-quality of plan artifacts, not correctness. Every style-drift finding must cite a STYLE.md rule ID; every premature-abstraction finding must cite an existing duplicate by `file:line`. It never writes `PLAN_STYLE_AUDIT.md`; the orchestrator does.
- `scope-probe` returns `STATUS: refused` + `MODE: MEDIUM` when axis evidence is insufficient; this is not an error state, it is the designed graceful-degradation path. All line-prefix headers must appear before the fenced JSON block -- headers inside the fence cause `scope_probe_malformed` events and the host falls back to MEDIUM.
- `scope-reconciler-audit` severity elevation applies only to systemic non-dissent findings (same normalized-evidence-line in >=2 distinct chunks). Dissent findings are never elevated.
- `research-judge` is forbidden from proposing new design recommendations; every claim must trace back to the terrain `MAP.md` artifact, BRAINSTORM.md, or a panel perspective file. The self-check (Step 7) runs on every invocation. Its Evidence-gaps section now suggests `/z-explore --depth=deep` investigation topics instead of the legacy `/z-map` re-run wording; the `dispatch_decision.map` field name is retained only for legacy terrain-wrapper compatibility.
- `implementer` contract fields (RATIONALE, TRIED, DEVIATIONS) feed Tier 2 design rationale. TRIED entries are self-reported and unverifiable by reviewers beyond code consistency. DEVIATIONS are validated by the reviewer against the diff. RATIONALE is required on every return.
- **`implementer`'s effective model is no longer a fixed Sonnet/Opus choice by task complexity.** The frontmatter `model: gpt-5.5:low` is a static fallback label; the orchestrator's native model-routing layer resolves the real effective model from `low|medium|high|retry` routing tiers (driven by the task's `**Complexity:**` stamp, or `retry` on a reviewer-triggered re-attempt) and passes routing-provenance fields (`subagent_model_source`, `subagent_model_route`, `subagent_model_route_kind`, `subagent_model_override_applied`, `subagent_model_override_support`) that implementer must echo verbatim into its `implement_start`/`implement_end` telemetry. The old hardcoded `Agent(model="opus")` retry dispatch is gone -- retries now go through the same routing layer with a `retry` tier.
- **`implementer`'s guardrail-block policy is strict.** If a `PreToolUse` hook blocks an `Edit`/`Write`/`MultiEdit` (most commonly `block-shared-tree-edit.sh`, the shared-tree worktree-isolation guard), that is a stop signal, never an obstacle to route around. Implementer must NOT retry the same write through a Bash file-write workaround (`python3 -c "open(...,'w')"`, heredocs, `tee`, `sed -i`, `> path`, `cp`/`mv` into the path) -- it must return `status: "unable_to_complete"` with reason `guardrail_blocked`, quoting the hook's stderr, so the orchestrator (or a human) can resolve the contention.
- `implementer`'s new optional `intent_flags_path`, `execution_strategy_path`, `workstreams_path` inputs preserve the intent-approval conversation (concern flags/audit notes, execution DAG/checkpoint guidance, parallelism constraints) as attention guidance only -- they may narrow how a task is implemented but must never expand scope beyond the frozen INTENT.
- `tier1-doc-updater` is a mechanical agent -- no reasoning, no prose writing. It applies diff-only surgical updates to AUTO-START/AUTO-END delimited sections only. It never writes to `docs/human/` or `docs/llm/` directly; all output goes to staging. The `scripts/reconcile-tier1-staged.py` script handles the final merge -- when the agent is actually invoked (see the drift note above, it currently is not).
- `pre-reviewer` is opt-in only, gated by `Z_HARNESS_PRE_REVIEW=1`. It runs on the cheapest available model and produces preliminary findings. It never blocks; real reviewers get the final say.
- `context-curator` is mechanical only -- folds telemetry into SESSION.md, never edits production code or the live `/z-handoff` `SESSION_CONTEXT.md`. It now runs at durable `/z-execute` settle points (single-task batch, parallel batch, or an INTENT BFS level boundary once LEDGER/done-set state is flushed) rather than a single fixed batch breakpoint, and is keyed off a caller-supplied `completed_task_ids` list.
- `ideator-clusterer` is only dispatched when WIDE_N > 3 (wide mode); for WIDE_N <= 3, the orchestrator presents raw framings directly. If the agent fails or returns K=0, `/z-brainstorm` falls back to presenting N raw framings. `ideator-clusterer` is distinct from `scope-reconciler-brainstorm`: the former operates on the divergence axis (N peer framings, same topic), the latter on the chunk axis (sub-topics in scope).
- `cluster-planner` no longer dispatches `complexity-classifier` -- the Phase 5 complexity-stamping step was removed along with the per-cluster `TASKS.md`; task enumeration and complexity stamping are deferred to BFS time under `/z-execute`. Its Phase 6 return now uses `FILES_COUNT` (length of `FILES_TOUCHED`, derived directly from `MANIFEST.json`) in place of the legacy `TASKS_COUNT`.
- `reviewer`'s new optional `intent_flags_path`/`execution_strategy_path`/`workstreams_path` inputs apply only in INTENT mode, read after INTENT+LEDGER and before the durable tier (kernel/invariants/style). Reviewer must report a blocker if the diff ignores a flagged concern/decision, expands beyond INTENT, or silently chooses a new product/intent direction without an explicit `decision_needed` halt.

These agents are invoked by commands; users do not call them directly.

## Examples

- `/z-plan` dispatches `planning-router` only when deterministic route signals conflict or confidence is too low for an automatic route; it recommends only `/z-do`, `/z-plan`, `/z-plan-split`, `/z-brainstorm`, or `/z-sharpen` as primary targets now. After TASKS.md is finalized, `/z-plan` dispatches `scope-extractor` to seed the active-plan registry.
- `/z-plan-split` dispatches `cluster-planner` once per cluster; each cluster planner writes `INTENT.md` + `MANIFEST.json` and may call `doc-fetcher` but no longer calls `complexity-classifier` (complexity stamping moved entirely to BFS time under `/z-execute`) or external consultants.
- `/z-execute` dispatches `scope-extractor` at Phase 0 to seed scope, then per-task dispatches `spec-precheck`, `implementer` (routed via the native model-routing layer, not a fixed Sonnet/Opus choice), optional `remote-runner`, and `reviewer` (or `self-reviewer` when `Z_HARNESS_CONSULT=off`). `spec-precheck` and `reviewer` both consume `relevant_docs` LLM JSONs. When `Z_HARNESS_PRE_REVIEW=1`, `pre-reviewer` runs a fast first-pass scan in parallel (up to 3) before the real reviewers.
- `/z-execute`'s INTENT BFS scheduler coalesces `REMOTE_VERIFY` tasks within a level into a single `remote-runner` dispatch keyed by `sandbox_key: <slug>/level-<N>`, instead of one `remote-runner` call per task.
- `/z-execute` Phase 9 dispatches `review-agent` as a post-run pass. At durable settle points, `context-curator` folds telemetry into SESSION.md (never the live `/z-handoff` `SESSION_CONTEXT.md`). When `run-memory-review.sh` signals `AXIOM_READY`, it also dispatches `axiom-extractor` in parallel. Both are proposals-only -- `/z-suggest-memory` and `/z-axiom-approve` handle any downstream writes.
- `/z-audit-plan-style` dispatches `plan-style-reviewer` for the plan artifacts before any code is written; `plan-style-reviewer` may fan out to consultant voices; the orchestrator builds `PLAN_STYLE_AUDIT.md` from the returned JSON.
- `/z-maintain-docs` dispatches `doc-updater` for stale concepts and can then audit the proposed update with both consultant proxies in `doc-audit` mode; `doc-updater`'s returned `summary` field is what `/z-maintain-docs` writes into `docs/llm/INDEX.json`.
- `/z-mr-review` dispatches `mr-reviewer` for the whole diff or per chunk; `mr-reviewer` may fan out to consultant voices and can dispatch an Opus sub-agent for deep abstraction analysis when `deep: true`.
- `/z-debug` Phase 2.5 dispatches `bisect-isolator` when the bug is a regression with a known-good baseline and the repro is scriptable. Phase 10 dispatches `review-agent` with `parent_command: debug` and `debug_md_path` pointing to DEBUG.md. `/z-debug` Phase 6's fix-stage consult now goes through `consultant-primary`/`consultant-secondary`'s `light-fix` mode (shared with `/z-fix`).
- `/z-audit` and `/z-brainstorm` dispatch `scope-probe` as Phase 0. On HEAVY classification, the host fans out N parallel sub-runs; after they complete it dispatches `scope-reconciler-audit` or `scope-reconciler-brainstorm` to merge results.
- `/z-brainstorm` in wide mode (WIDE_N > 3) dispatches multiple ideator waves, then dispatches `ideator-clusterer` to collapse N framings into K distinct directions. The clusterer's report replaces the N raw framings in the Phase 3 ranked briefing. Cross-cluster consensus (if any) is surfaced as a separate callout.
- `/z-research` dispatches `research-judge` once after all adversarial-panel perspective agents complete. The judge returns full RESEARCH.md content; the orchestrator writes the file. Its Evidence-gaps suggestions now cite `/z-explore --depth=deep`, not `/z-map`.
- `/z-personas` (roles subcommand) validates persona-to-role bindings; `resolve-persona.py validate` hard-fails if `consultant-primary` or `consultant-secondary` is bound to a persona with `contract: review-verdict`, or if `reviewer`/`self-reviewer` is bound to a persona with `contract: freeform`.
