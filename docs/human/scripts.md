## Overview

The scripts concept covers the shell and Python utility scripts that form the operational backbone of the z-harness pipeline. The original cohort handles structured event telemetry (logging individual events and wrapping entire phases with start/end timing), memory document regeneration across all concept JSONs, plugin version introspection, the lifecycle gate logic for the memory-review agent, MR-review dismissal signature extraction across archived run snapshots, rsync-based remote sandbox synchronization, layered TOML configuration and workflow-question resolution, run terminal-state classification, overnight preflight collision detection, TASKS.md normalization, AskUserQuestion callsite auditing, morning-report generation, and the local preflight harness.

A third script — `scripts/persona-stats.py` — is a read-only analysis tool for the persona-rotation experiment. It reads `z-harness/metrics.jsonl`, joins `persona_random_selected` (draw) events with `persona_attempt_outcome` (terminal) events via `draw_id` / `attempt_id`, groups by `persona_id × role × complexity_tier`, and reports outcome metrics (review_cycles, retries, blocker_count, wall_ms, completion rate) including the **delta vs `boring-anchor`** control within each stratum. `fallback_empty_pool` draws are quarantined and reported separately. Incomplete attempts (no `persona_attempt_outcome`) are filtered out. Supports `--json` for machine output and `--min-diff-size N` to drop trivial tasks. Usage: `python3 scripts/persona-stats.py [--json] [--min-diff-size N]`.

A second cohort — added by the notion-followup-sink plan — implements the follow-up sink subsystem: a persistent, durable queue of actionable work items discovered during harness runs. It consists of eleven scripts with single-responsibility contracts. `sink-lock.sh` provides a generic per-entry `fcntl.flock` + heartbeat + stale-takeover primitive (usable by any tool). `sink-add.sh` / `sink-add-helpers.py` is the writer primitive callable by any skill; it validates, dedup-checks, acquires the global lock, writes a JSONL event and a prompt-page, rebuilds the materialized view, and optionally triggers a Notion push. `sink-claim.sh` / `sink-claim-helpers.py` implements an atomic `open→running` claim with the mandatory lock-ordering invariant (per-entry lock first, then global). `sink-status-set.sh` / `sink-status-set-impl.py` drives the seven-state machine (`open → running → verify → done / failed / blocked / dismissed`) with a completion_mode mutex. `sink-view-rebuild.sh` / `sink-view-reducer.py` replay `index.jsonl` into a materialized `index.view.json` via atomic rename. `sink-audit-validate.py` runs an 11-point check on audit evidence before a `done` transition. `sink-auto-close-check.py` gates the `auto_closed_low_risk` completion mode against allowlist/denylist globs. `notion-push.py` performs a one-way idempotent push to Notion with exponential-backoff retry. `followup-reconcile-notion.sh` / `followup-reconcile-notion-impl.py` sweep all entries with `notion_sync_pending` and re-attempt push. `parse-followups-block.py` is a tolerant parser for the `**FOLLOWUPS:**` fenced JSON block emitted by reviewers. `validate-followup-schemas.sh` runs JSON Schema validation assertions against entry and audit-evidence fixture files. `scripts/config.py` gained a new `[followup]` section (9 keys + denylist), 3 new validators, the `workflow.spec_retro_discovery` question ID, and a `defer-to-sink` result in `RESULT_MAP`.

## Edge cases / gotchas

- `log-phase.sh` `check_wall_ms`: threshold is 604_800_000 ms (7 days). Values above this indicate seconds-vs-ms confusion. Values below 0 indicate clock skew. Both cases emit `telemetry_anomaly` with a `t_start`, `t_end`, `computed_wall_ms`, and `reason` field, then exit 0 to suppress the bogus `*_end` event.
- `config.py` startup guards run at module load via `_run_startup_guards()`. They enforce: every key in `QUESTION_IDS` must exist in `VALIDATORS`; every entry must have a non-null `skill_default`; every `(question_id, choice)` key in `RESULT_MAP` must reference a known question_id and valid choice. Violations exit 2 immediately.
- `config.py resolve-question` returns a JSON envelope with `result` in `{ask, skip, prefill, halt, defer-to-sink}` (the resolver result-domain). The `RESULT_MAP` handles translation. `workflow.spec_retro_discovery` can return `defer-to-sink`, which signals the caller to invoke `sink-add.sh` instead of prompting the user.
- `config.py resolve-question` honors `Z_HARNESS_ASK_ALL=1` as a short-circuit that forces `result: ask` regardless of config or memory. `Z_HARNESS_EXPLAIN_RESOLUTION=1` activates verbose explain output on stderr. `Z_HARNESS_NO_ASK=halt` activates overnight/halt-from-ask behavior via `_apply_overnight_overrides`.
- `config.py check-no-ask` result is `halt` (fail-closed) for unregistered question IDs when `Z_HARNESS_NO_ASK=halt`; it also emits `unknown_ask_blocked` event.
- `config.py set` performs a read-modify-write using atomic temp-file rename. Default scope is `project`; pass `--scope=global` for the global config.
- `config.py export-env` emits a `config_resolved` event exactly once per `Z_HARNESS_RUN` via an `O_EXCL` stamp file in `$TMPDIR`. `roles.*` keys are not exported as env vars.
- `sink-lock.sh acquire` forks a **background daemon** that holds the `.flock` sentinel's `LOCK_EX` open for the lock's entire lifetime. The holder PID recorded in the JSON is the **daemon's own `os.getpid()`**, NOT `os.getppid()` (the shell caller). The daemon blocks on `signal.pause()` until `release` sends SIGTERM; its SIGTERM handler zeros the JSON content and closes the flock fd. Stale-takeover (exit 2) applies even when `LOCK_EX|LOCK_NB` fails: if the recorded PID is dead or heartbeat is expired, the takeover path kills the old daemon, waits for flock freedom, then spawns a replacement daemon.
- `sink-lock.sh` stale-takeover (exit 2) fires when `pid_alive(held_pid)` returns False OR `last_heartbeat` age exceeds TTL (default 7200s). Either condition alone is sufficient.
- `sink-add-helpers.py` performs dedup in two phases: a cheap pre-lock check against `index.view.json`, then a TOCTOU-safe recheck under the global lock. The dedup key is SHA-256 of `name + NUL + recommended_command + NUL + source_artifact`; entries in `done` or `dismissed` status are excluded from dedup.
- `sink-add-helpers.py` cited paths: when `len(cited_paths) <= 16`, individual `git hash-object` SHAs are recorded. When `> 16`, the common ancestor directory's tree hash is used instead. If the ancestor is less than 2 levels deep from the repo root (depth < 2), the write is rejected with exit 6 (diffuse-cited-paths).
- `sink-add-helpers.py` depth guard: `Z_HARNESS_FOLLOWUP_CALLER_DEPTH` env var (default 0) controls nesting depth. `MAX_DEPTH = 1` means caller_depth > 1 is rejected with exit 4 to prevent follow-up chains.
- `sink-claim-helpers.py` lock-ordering invariant is mandatory: per-entry lock FIRST, then global. Violating this order risks deadlock. The stale-takeover path (when `sink-lock.sh` returns exit 2) requires a brief upgrade to the global lock to append recovery events before proceeding.
- `sink-claim-helpers.py` depth-1 refusal: entries with `depth == 1` are considered inert (spawned from an already-running follow-up). The claim operation refuses with exit 7 rather than letting consumers attempt to process self-referential chains.
- `sink-status-set-impl.py` state machine: `ALLOWED_TRANSITIONS` defines legal edges. The `done` terminal state only allows transition to `dismissed`; `dismissed` is terminal with no outgoing edges. Attempts to leave `dismissed` exit 3.
- `sink-status-set-impl.py` completion_mode mutex: only one of `human_confirmed`, `audit_confirmed`, or `auto_closed_low_risk` may be set per entry. Re-setting to a different non-null mode exits 6.
- `sink-view-rebuild.sh` verifies the global lock is held via two complementary checks before delegating to the reducer. It must never be called without the caller holding the lock. Exit 4 signals the caller made a programming error (called without the lock).
- `sink-view-reducer.py` is forward-compatible: unknown event kinds emit a stderr warning and are skipped silently. Unknown fields within known events are also ignored.
- `sink-audit-validate.py` check 11 (`reviewer_notes non-empty`) is the last check; all earlier checks short-circuit on the first failure. The output JSON always includes `rejected_check` (the failing check number) and `reason` text.
- `sink-auto-close-check.py` denylist takes precedence over allowlist: a path that matches both is treated as denied. The allowlist and denylist globs are read from config (`followup.auto_close_low_risk_path_allowlist` / `_denylist`), supporting `**` wildcard with gitignore-style semantics.
- `notion-push.py` idempotency: before creating a new page, it queries Notion for an existing page with `z_harness_entry_id` matching the entry's `id`. If found and matching, it returns exit 0 (already synced). If found but mismatching, it returns exit 5 (idempotency mismatch). Token resolution order: `Z_HARNESS_NOTION_TOKEN` env → `secrets.toml`.
- `parse-followups-block.py` is maximally tolerant: it never aborts on per-entry validation errors; it logs and skips individual bad entries. The only fatal exit (1) is an I/O error reading stdin.
- `validate-followup-schemas.sh` requires `pip3 install jsonschema`. It exits 2 if the library or schema/fixture files are missing (before any assertions run).
- `remote-sandbox-sync.sh` two-level layout: the `base/` directory is seeded once per slug using an atomic remote `mkdir` lock. Concurrent invocations poll for the `.base-ready` marker (up to 600s). The per-task overlay uses `--link-dest` so unchanged files are hard-linked rather than copied.
- `remote-sandbox-sync.sh` resolves REMOTE_HOME via `ssh <host> 'printf %s "$HOME"'` rather than relying on tilde expansion, which is unreliable inside `--link-dest`.
- `remote-sandbox-sync.sh` TASK_ID rejects the literal value `base` (reserved for the shared base directory) in addition to path-traversal patterns.
- `run-memory-review.sh` uses a 4-state terminal taxonomy in `memory_review_terminal` events: `skipped_broken_context` (missing args, no plan dir, tags file absent), `not_applicable` (empty diff, all tasks skipped, debug_md missing); `ready` and `dispatched` are orchestrator-owned.
- The env var controlling the plan base dir is `Z_HARNESS_PLAN_DIR` (singular), not `Z_HARNESS_PLANS_DIR`.
- `log-phase.sh` uses a `python3` fallback (`time.time()*1000`) to get millisecond timestamps because macOS BSD `date` does not support `%3N`.
- `log-event.sh` validates JSON payloads via `python3`; malformed payloads are silently wrapped in `{"raw": ...}` rather than failing.
- `lint-askuser.sh` classification is file-level, not callsite-level: if a file has `AskUserQuestion` AND `resolve-question` anywhere in it, all callsites in that file are tagged `REGISTERED` regardless of pairing.
- `morning-report.py` emits a `CRITICAL: HEAD SHA mismatch at resume` banner in the chain summary section when a `head_sha_mismatch_at_resume` event is found in `events.jsonl`.
- `preflight.sh` maps `lint-askuser.sh` exit 1 to an advisory warning only; exits 2 and 3+ from `lint-askuser.sh` are propagated as hard failures.

## Examples

- Start a named phase and capture the timing token:
  `TOKEN="$(bash scripts/log-phase.sh start "tasks/T020" precheck '{"id":"T020"}')"`
- End the phase with status:
  `bash scripts/log-phase.sh end "$TOKEN" '{"status":"ok","references_checked":11}'`
- Gate the memory-review agent from implement-all:
  `mapfile -t LINES < <(bash scripts/run-memory-review.sh "$RUN" "implement-all")`
- List all registered question IDs:
  `python3 scripts/config.py list-question-ids`
- Resolve a question (returns JSON envelope with result, default, source, strength):
  `python3 scripts/config.py resolve-question workflow.audit_to_amend`
- Check whether a question can proceed in overnight mode:
  `python3 scripts/config.py check-no-ask --question-id workflow.slug_confirm`
- Resolve the spec_retro_discovery question (may return defer-to-sink):
  `python3 scripts/config.py resolve-question workflow.spec_retro_discovery`
- Add a follow-up entry to the project sink:
  `bash scripts/sink-add.sh --sink=project --priority=P2 --name='Fix linter gap' --recommended-command='/z-fix' --source-artifact='z-harness/plans/my-slug/REVIEW.md' --cited-paths='scripts/lint-askuser.sh'`
- Acquire a per-entry lock:
  `bash scripts/sink-lock.sh acquire /path/to/entry.lock my-holder-id`
- Heartbeat an acquired lock:
  `bash scripts/sink-lock.sh heartbeat /path/to/entry.lock`
- Claim an open follow-up entry for processing:
  `TICKET="$(bash scripts/sink-claim.sh --entry=20260529T000000Z-fix-linter-gap --run="$RUN" --sink-root=z-harness/followups)"`
- Transition a follow-up entry to done with audit evidence:
  `bash scripts/sink-status-set.sh --entry=<id> --to=done --by="$RUN" --sink-root=z-harness/followups --evidence=audit_evidence.json --completion-mode=audit_confirmed --via-claim-ticket="$TICKET"`
- Rebuild the materialized view (caller must hold global lock):
  `bash scripts/sink-view-rebuild.sh z-harness/followups`
- Validate audit evidence against an entry:
  `python3 scripts/sink-audit-validate.py audit_evidence.json entry.json`
- Check if a follow-up qualifies for auto-close:
  `python3 scripts/sink-auto-close-check.py --entry=entry.json --diff=changes.diff --test-exit=0`
- Push a follow-up entry to Notion:
  `python3 scripts/notion-push.py --entry-json=entry.json --config-database-id=<db-id>`
- Sweep pending Notion syncs for project sink:
  `bash scripts/followup-reconcile-notion.sh --project-sink-root=z-harness/followups`
- Parse FOLLOWUPS block from reviewer output:
  `python3 scripts/parse-followups-block.py --reviewer-output=REVIEW.md`
- Run JSON Schema validation assertions for followup fixtures:
  `bash scripts/validate-followup-schemas.sh`
- Classify the terminal state of a run:
  `bash scripts/run-status.sh classify 20260527T155455Z-amend-runtime-core`
- Run local preflight checks before a commit:
  `bash scripts/preflight.sh`
