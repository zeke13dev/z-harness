## Overview

The scripts concept covers the shell and Python utility scripts that form the operational backbone of the z-harness pipeline. The core cohort handles structured event telemetry (`log-event.sh` / `log-phase.sh`), memory document regeneration (`regenerate-memories-flat.py`), plugin version introspection (`version.sh`), memory-review lifecycle gating (`run-memory-review.sh`), MR-review dismissal signature extraction (`extract-dismissals.py`), rsync-based remote sandbox synchronization (`remote-sandbox-sync.sh`), layered TOML configuration and workflow-question resolution (`config.py` / `config.sh`), the lockless per-run active-plan registry and cross-session lease subsystem (`active-plan-registry.py`), persona-rotation analysis (`persona-stats.py`), and the git-safety PreToolUse hook (`block-dangerous-git.sh`). Test scripts (`test_config.py`, `test_log_phase.sh`, `test_block_dangerous_git.sh`) provide regression coverage. `log-event.sh` routes all base-path resolution through `z_harness_base()` from `plan-path.sh`, which implements a 5-tier fallback chain and supports the `Z_HARNESS_BASE_DIR` external-base redirect required for benchmark task isolation.

This refresh narrows this concept's declared scope back to the 15 files above. Two script families that were previously duplicated inside this doc now have their own dedicated concept docs and are documented there instead: the follow-up sink subsystem (`sink-*.sh`/`.py`, `notion-push.py`, `followup-reconcile-notion*`, `parse-followups-block.py`, `validate-followup-schemas.sh`) lives in `docs/human/followup-sink.md` / `docs/llm/followup-sink.json`, and the overnight-chain support scripts (`run-status.sh`, `normalize-task-state.sh`, `overnight-preflight.sh`, `morning-report.py`) live in `docs/human/overnight-run.md` / `docs/llm/overnight-run.json`. Two scripts previously documented here — `lint-askuser.sh` and `preflight.sh` — do not have a declared home in either of those docs or this one after the narrowing; they still exist in `scripts/` but currently fall outside every concept doc's `source_file` list. This is flagged for the doc-maintenance caller to assign.

`scripts/block-dangerous-git.sh` is a Claude Code PreToolUse hook that intercepts every Bash tool call and classifies any `git` subcommand it finds. It operates in two modes: (1) history-rewrite verbs (`reset --hard`, `commit --amend`, `push --force`, `push --force-with-lease`, `push -f`, and `+`-prefixed refspec pushes) trigger an upstream-reachability check — the hook resolves HEAD and runs `git branch -r --contains <sha>`; only upstream-reachable rewrites are blocked. (2) working-tree-destructive verbs (`clean -f*`, `checkout .`, `restore .`, `branch -D`) are blanket-blocked without any subprocess. The hook normalizes commands before classification: it tokenizes each chained segment, strips git global options (`-C`, `-c`, `--git-dir`, etc.) and env-var prefixes, then runs verb detection against canonical `git <subcommand> <rest>` forms. This prevents evasion via `git -C /tmp reset --hard` or `GIT_DIR=x git reset --hard`. Override: `Z_HARNESS_GIT_GUARDRAILS_OVERRIDE=1` allows the command through and appends an audit entry to `<base>/git-guardrails-audit.log`. The hook is fail-closed: any git error during the upstream check results in a block. Installed via `/z-git-guardrails install`.

`scripts/active-plan-registry.py` is a lockless per-run active-plan registry that has grown substantially since its original shape: it now has **11 subcommands**, not 8. Each run owns exactly one record at `<active_plans_dir>/<run-id>.json`; all writes are atomic (`tmpfile + os.replace`) and no global lock is taken. The original cohort: `session-id`, `register` (now accepts an optional `--watchdog-pid`), `heartbeat` (also accepts `--watchdog-pid`), `update-scope`, `list [--json]`, `overlaps [--strict] [--scope-json]`, `reap`, `deregister` (now also SIGTERMs the run's watchdog sweep process, read from a `.watchdog.pid` file, on a best-effort basis). New since the last refresh: `claim`, `release`, and `wait-for` implement a cross-session **lease/wait subsystem** (design invariants F1-F5, see gotchas below) that lets one run park itself behind senior peers holding overlapping paths, or claim/release named paths outright via a lexicographic run-id tiebreak. As of this refresh, `claim`/`release`/`wait-for` are implemented and unit-tested but **not yet called by any shipped skill** — they're available infrastructure, not yet wired into a live workflow. `Z_HARNESS_REGISTRY_ENABLED=0` disables all coordination writes across every mutating subcommand; non-mutating reads (`list`, `session-id`) are always permitted.

`scripts/config.py` gained two new dynamic-key config sections in the codex-prod-support release (2026-07-05): `model_classes.<name>.{model,thinking,reasoning}` (local model-class routing, defaulting to `cheap`→haiku, `standard`→sonnet, `deep`→opus) and `model_routing.{native_agents.default, implementer.low|medium|high|retry}` (implementer-tier→model-label routes, e.g. mapping to `gpt-5.5` under an omp host). These are validated structurally rather than via a fixed per-key `VALIDATORS` entry, since class/agent names are open-ended. `_run_startup_guards()` also gained a fourth guard (2b): every `QUESTION_IDS` entry must carry a `halt_category` present in `HALT_CATEGORY_ENUM`, in addition to the pre-existing VALIDATORS/skill_default/RESULT_MAP checks.

`scripts/persona-stats.py` is a read-only analysis tool for the persona-rotation experiment. It reads `<base>/metrics.jsonl`, joins `persona_random_selected` draw events to `persona_attempt_outcome` terminal events by `attempt_id`, and groups by `persona_id × role × complexity_tier`. Within each stratum it computes outcome metrics and a delta versus the baseline — baseline resolution order: `no-persona` (primary null baseline), then `boring-anchor` (secondary bland control), then `None`. `fallback_empty_pool` draws are quarantined to a separate section and never folded into any persona's stats or baseline. Supports `--json`, `--min-diff-size N`, `--since DATE`, and `--include-unknown-run`.

`scripts/remote-sandbox-sync.sh` gained a `--sandbox-key <slug>/<subpath>` flag (2026-07-01, remote-verify-coalesce plan) that overrides the per-task overlay path — used by coalesced per-BFS-level `REMOTE_VERIFY` dispatch (one build per level rather than one per task), where the overlay is keyed `<slug>/level-<N>` instead of `<slug>/<task-id>`. The shared warm base stays keyed by `SLUG` alone whether or not `--sandbox-key` is used; legacy callers that omit the flag get byte-identical behavior to before it existed.

## Edge cases / gotchas

- `block-dangerous-git.sh` is fail-closed: if the `git branch -r --contains` subprocess errors (detached HEAD, no remote, git error), it blocks the rewrite verb rather than allowing it through.
- `block-dangerous-git.sh` only shells out for rewrite verbs that need the upstream-reachability check; working-tree-destructive verbs are blocked synchronously without any subprocess.
- `block-dangerous-git.sh` normalizes commands before verb classification: it splits on `&&`, `||`, `|`, `;`, `&` operators and strips git global options (`-C`, `-c`, `--git-dir`, `--work-tree`, etc.) so `git -C /tmp reset --hard` or `GIT_DIR=x git clean -fdx` cannot evade detection.
- `block-dangerous-git.sh` treats `+`-prefixed refspec pushes (`git push origin +main`) as force pushes — they flow through the same upstream-reachability check as `--force`. A plain `git push origin main` (no `+`) is not a force push and passes through unconditionally.
- `Z_HARNESS_GIT_GUARDRAILS_OVERRIDE=1` allows a blocked command through exactly once per invocation and appends an audit entry; it does not permanently disable the hook.
- `block-dangerous-git.sh` accepts empty or non-JSON stdin gracefully (fails safe by allowing). Non-Bash tool calls pass through immediately; only `tool_name == "Bash"` payloads are inspected.
- `log-event.sh` resolves all artifact paths via `z_harness_base()` from `plan-path.sh` (5-tier fallback). When `Z_HARNESS_BASE_DIR` is set, the mid-flight legacy fallback is skipped entirely to preserve the model.patch invariant.
- `log-phase.sh` `check_wall_ms`: threshold is 604_800_000 ms (7 days). Values above this indicate seconds-vs-ms confusion. Values below 0 indicate clock skew. Both cases emit `telemetry_anomaly` and suppress the bogus `*_end` event.
- `log-phase.sh` uses a `python3` fallback (`time.time()*1000`) to get millisecond timestamps because macOS BSD `date` does not support `%3N`.
- `log-phase.sh` `begin`/`finish` modes persist timing state in `$TMPDIR/z-harness-phase/<key>.start`. They exist specifically because a shell variable (`T0=$(date ...)`) dies across Bash tool-call boundaries, causing `wall_ms: 0`. `finish` is fail-open: if no stamp file exists, it emits nothing rather than a bogus `wall_ms:0` event.
- `log-event.sh` validates JSON payloads via `python3`; malformed payloads are silently wrapped in `{"raw": ...}` rather than failing.
- `log-event.sh` mid-flight legacy detection: writes to the old flat path if the run dir already exists there (but skips this when `Z_HARNESS_BASE_DIR` is set).
- `config.py` startup guards run at module load via `_run_startup_guards()`. Guard 2b now also requires every `QUESTION_IDS` entry to carry a `halt_category` in `HALT_CATEGORY_ENUM`. Violations exit 2 immediately.
- `config.py resolve-question` returns result in `{ask, skip, prefill, halt, defer-to-sink}`. `workflow.spec_retro_discovery` can return `defer-to-sink`, which signals the caller to invoke `sink-add.sh`.
- `config.py resolve-question` honors `Z_HARNESS_ASK_ALL=1` (forces `result: ask`) and `Z_HARNESS_NO_ASK=halt` (activates overnight overrides). Setting both simultaneously exits 5.
- `config.py check-no-ask` is fail-closed: unregistered question IDs return `halt` when `Z_HARNESS_NO_ASK=halt` and emit `unknown_ask_blocked`.
- `config.py get-batch` always exits 0 (best-effort); unknown keys return null with a stderr warning. Meta keys are excluded without error.
- `config.py resolve-halt-category` returns the bare tag string (not JSON); fail-safe default `"ask"` for unknown or untagged qids.
- `config.py model_classes`/`model_routing` (new, 2026-07-05): `model_routing.native_agents.default` is empty by default so native agents keep their checked-in frontmatter model unless explicitly overridden; `model_routing.implementer.*` reproduces the pre-existing `/z-execute` implementer tier→model labels (low/medium=sonnet, high/retry=opus) as configurable routes.
- `active-plan-registry.py` lockless invariant: the lockless design is safe ONLY because overlap is advisory. No code may make overlap a hard gate without first replacing lockless delete with compare-and-delete or a registry lock.
- `active-plan-registry.py` wait/lease cross-cutting invariant (F1-F5): wait/lease gates only the waiter's OWN run; it takes no lock; it never writes a peer's record (except the reaper's single-writer stale-marking exception); every wait has a finite budget + loud timeout; overlap is never a hard gate; the holder is never preempted.
- `active-plan-registry.py register` exits 3 on failure — callers MUST gate on this exit code; all other subcommands are non-fatal (exit 0 even on error, self-logging via `registry_error` events) except `wait-for`, whose non-zero exits (2 usage, 10 timeout, 130 signal) are also LOUD by design.
- `active-plan-registry.py heartbeat` does NOT fabricate a record when `<run-id>.json` is absent (never registered, reaped, or deregistered). Creating an empty record would pollute overlap detection with zombie records.
- `active-plan-registry.py overlaps` blocking exit code 20 fires only in strict mode (`--strict` or `Z_HARNESS_STRICT_OVERLAP=1`) AND when both peers share an `explicit`-confidence path match. Stale peers (status:stale OR heartbeat > `Z_HARNESS_REGISTRY_STALE_SECS`) are included in the report but marked non-blocking.
- `active-plan-registry.py reap` case (a): deletes only when the record host matches THIS host and the PID is dead. Case (b): deletes when `age_secs > stale_threshold * 2` regardless of host. Case (c): marks `status:stale` (no delete) when `age_secs > stale_threshold` and host is remote/unknown. `FileNotFoundError` on unlink is always benign (two reapers racing). `reap` is the one deliberate exception to the single-writer invariant.
- `active-plan-registry.py session-id`: on Linux derives `<ppid>-<start_epoch>` from `/proc`; on macOS derives `<ppid>-<current_epoch>` (no subprocess, avoiding CoreFoundation fork-safety crash). Callers should `export Z_HARNESS_SESSION_ID="$(session-id)"` once at run start so repeated calls reuse the env var.
- `active-plan-registry.py` sets `OBJC_DISABLE_INITIALIZE_FORK_SAFETY=YES` at import time to prevent CoreFoundation fork-safety crashes when bash invokes Python with an existing CF-initialized parent.
- `active-plan-registry.py claim` resolves contention by run_id lexicographic tiebreak: a claim concedes only to a SENIOR peer (lower run_id) holding the same path; junior peers never force a concession. A tiebreak loser's persisted `held_paths` must not contain the conceded path.
- `active-plan-registry.py wait-for` clears the `waiting_on` field on every exit path via try/finally (EH-005), so no paused zombie record can leak even on SIGINT/SIGTERM (exit 130) or budget timeout (exit 10). An age-stale target with status still `running` already counts as cleared, independent of the reserved `Z_HARNESS_WAIT_REQUIRE_MERGE` flag.
- `active-plan-registry.py deregister` reads the run's slug's `.watchdog.pid` file and SIGTERM→grace→SIGKILLs the watchdog sweep process; this is best-effort and wrapped so a kill failure never breaks deregister.
- `active-plan-registry.py claim`/`release`/`wait-for` (the F1-F5 lease subsystem) are implemented and unit-tested but, as of this refresh, **no shipped skill invokes them** — only `session-id`/`register`/`heartbeat`/`update-scope`/`list`/`overlaps`/`reap`/`deregister` are wired into live commands. Treat the lease trio as available-but-not-yet-consumed infrastructure when reasoning about current system behavior.
- `persona-stats.py` baseline resolution: `no-persona` is the primary null baseline (true null prefix); `boring-anchor` is the secondary bland control. Both appear as their own rows in every section — neither is quarantined or hidden.
- `persona-stats.py` `--since` filter: events with a missing or unparseable `ts` field are excluded (conservative) when `--since` is active.
- `persona-stats.py` events with `run == "unknown-run"` are excluded by default (dev noise from ad-hoc subcommand/test draws); pass `--include-unknown-run` to opt back in.
- `run-memory-review.sh` uses a 4-state terminal taxonomy: `skipped_broken_context`, `not_applicable`, `ready`, `dispatched` (last two are orchestrator-owned). The `debug` parent adds a third skip condition: `debug_md_missing`.
- `run-memory-review.sh` emits `AXIOM_READY <diff-path>` only when `axioms.auto_extract_post_run` resolves to anything other than `"false"` (default is enabled). This line appears after the `STATUS: ready` block, not instead of it.
- The env var controlling the plan base dir is `Z_HARNESS_PLAN_DIR` (singular), not `Z_HARNESS_PLANS_DIR`.
- `remote-sandbox-sync.sh` `--sandbox-key <slug>/<subpath>` overrides only the overlay path (used by coalesced per-BFS-level `REMOTE_VERIFY` dispatch); the shared warm base stays keyed by `SLUG` alone. `--sandbox-key` must be exactly `<segment>/<segment>` and its subpath may not be `base`. Legacy callers that omit the flag are unaffected.
- `remote-sandbox-sync.sh` TASK_ID rejects the literal value `base` and all path-traversal patterns. `REMOTE_HOME` is resolved via `ssh printf` (not tilde expansion). All slug trees now nest under `<container>/sandbox/` (the extra level prevents a misdirected rsync from polluting alongside real slug dirs).
- `remote-sandbox-sync.sh` `Z_HARNESS_WORKTREE_ROOT`: when the orchestrator's cwd is the main checkout but edits land in a linked worktree, the default `git rev-parse --show-toplevel` resolves the main tree and ships stale files. Set `Z_HARNESS_WORKTREE_ROOT` to the worktree's absolute path to override. The script hard-errors (exit 2) if the path is set but does not exist on disk. The resolved source root is always printed to stderr (`syncing local root: <path>`) for transparency.
- `lint-askuser.sh` and `preflight.sh` are no longer declared as `source_file` entries in this doc after the followup-sink/overnight-run split, and they don't appear in either of those docs' `source_file` lists either — they exist in `scripts/` but currently have no concept-doc home. Flagged for the caller to assign.

## Examples

- Install git guardrails (via command): `/z-git-guardrails install`
- Allow one blocked git operation via override: `Z_HARNESS_GIT_GUARDRAILS_OVERRIDE=1 git reset --hard HEAD~1`
- Run the git-guardrails test suite: `bash scripts/test_block_dangerous_git.sh`
- Start a named phase and capture the timing token:
  `TOKEN="$(bash scripts/log-phase.sh start "tasks/T020" precheck '{"id":"T020"}')"`
- End the phase with status:
  `bash scripts/log-phase.sh end "$TOKEN" '{"status":"ok","references_checked":11}'`
- File-persisted phase timing (survives across Bash tool calls):
  `bash scripts/log-phase.sh begin "$RUN" precheck`
  `bash scripts/log-phase.sh finish "$RUN" precheck '{"status":"ok"}'`
- Gate the memory-review agent from implement-all:
  `mapfile -t LINES < <(bash scripts/run-memory-review.sh "$RUN" "implement-all")`
- Resolve a workflow question (returns JSON envelope):
  `python3 scripts/config.py resolve-question workflow.audit_to_amend`
- Resolve multiple config keys in one process:
  `python3 scripts/config.py get-batch workflow.planning_mode notifications.discord_enabled`
- Get the halt-category tag for a question ID:
  `python3 scripts/config.py resolve-halt-category workflow.slug_confirm`
- Check whether a question can proceed in overnight mode:
  `python3 scripts/config.py check-no-ask --question-id workflow.slug_confirm`
- Set a model-routing override (implementer tier -> model label):
  `python3 scripts/config.py set model_routing.implementer.high gpt-5.5`
- Derive a stable session ID (export once at run start):
  `export Z_HARNESS_SESSION_ID="$(python3 scripts/active-plan-registry.py session-id)"`
- Register a run in the active-plan registry:
  `python3 scripts/active-plan-registry.py register --run-id "$RUN" --slug "$SLUG" --command "/z-plan" --phase "plan" --session "$Z_HARNESS_SESSION_ID"`
- Check for overlapping active plans:
  `python3 scripts/active-plan-registry.py overlaps --run-id "$RUN" --strict`
- Claim a set of paths (best-effort lease):
  `python3 scripts/active-plan-registry.py claim --run-id "$RUN" --paths "scripts/config.py,scripts/config.sh"`
- Park a run behind senior peers until they clear:
  `python3 scripts/active-plan-registry.py wait-for --run-id "$RUN" --on "$SENIOR_RUN_ID"`
- Release claimed paths:
  `python3 scripts/active-plan-registry.py release --run-id "$RUN" --all`
- Deregister a run on completion:
  `python3 scripts/active-plan-registry.py deregister --run-id "$RUN" --status complete`
- List all active plans as JSON:
  `python3 scripts/active-plan-registry.py list --json`
- Reap dead/stale registry records:
  `python3 scripts/active-plan-registry.py reap`
- Run persona-rotation analysis:
  `python3 scripts/persona-stats.py --min-diff-size 5 --since 2026-06-01`
- Sync a git worktree (not main checkout) to remote sandbox:
  `Z_HARNESS_WORKTREE_ROOT=/abs/path/to/worktree bash scripts/remote-sandbox-sync.sh zeke-pc my-slug T030`
- Coalesced per-level sandbox sync (remote-runner internal usage):
  `bash scripts/remote-sandbox-sync.sh zeke-pc expand-sports-ml T030 --sandbox-key expand-sports-ml/level-2`
