## Overview

The multi-IDE export pipeline translates z-harness source files (`commands/`, `agents/`, and `personas/builtin/`) into target-specific layouts under `exports/`. The `skills/` top-level directory has been removed; per-host skill artifacts are generated by the export drivers from `commands/` content. Each export target has a dedicated driver at `runtime/drivers/<target>/export.py` that exposes a uniform `export(repo_root, export_root, *, options=None) -> ExportResult` signature. The canonical `ExportResult` dataclass (`dest`, `files`, `fidelity`, `warnings`) is defined in `runtime/drivers/_export_utils.py` and re-exported from `z_harness_cli/adapters/base.py` so CLI-layer code never imports upward into the runtime layer.

The four primary targets are Cursor (`fidelity="flattened"`, `.cursor/rules/*.mdc`), Codex CLI (`fidelity="flattened"`, `prompts/*.md` + `AGENTS.md`), Antigravity/agy (`fidelity="high"`, `.agent/` native layout + flat `prompts/`), and pi (`fidelity="high"`, `agents/`, `prompts/`, vendored subagent extension). pi is an export-only target with no adapter, HostDriver, or launch/inject support. For Cursor, Codex, and agy, each `z_harness_cli/adapters/<host>.py` adapter's `export_payload()` first delegates to the runtime `export()` for commands and agents, then runs the persona loop reading from `personas/builtin/`. To regenerate the committed `exports/<host>/` mirror use `python3 -m z_harness_cli export --host <host> --out exports/<target> --force`; the `--in-place` flag writes the host layout into the current working directory for live workspace use and does not populate the committed mirror. Shared utilities (`enumerate_sources`, `inline_includes`, `output_path_for`, `validate_capabilities`, `select_sources`, `resolve_strategy`, `run_self_test`) all live in `_export_utils.py`.

## How it interacts with others

- `commands` — `enumerate_sources` walks `commands/*.md`; `/z-export` is itself a command and is exported. `commands/` is now the single source of command content; no `skills/` source dir.
- `agents` — `enumerate_sources` walks `agents/*.md`; all agents including `scope-extractor` are exported.
- `personas-and-roles` — After the main runtime export, each adapter's `export_payload()` runs the persona loop via `runtime/drivers/<target>/persona_export.py`, reading from `personas/builtin/`. Cursor, Codex, and agy support persona export; pi has no persona export.
- `runtime-drivers` — `runtime/drivers/_export_utils.py` is the shared foundation; each target's `export.py` imports from it and never from `z_harness_cli`. Export-only drivers (windsurf, kiro, cline, copilot) also use `select_sources` and `resolve_strategy` from `_export_utils.py`.
- `central-config` — `resolve_strategy` reads `export.strategy` via `python3 scripts/config.py get export.strategy`; valid values are `pointer`, `curated`, `full`.
- `scripts` — `audit-tarball.sh` remains the export safety gate for packaged artifacts. Legacy `scripts/export-*.py` scripts have been removed.

## Edge cases / gotchas

- The `skills/` top-level source directory has been **removed**. `commands/` is now the single source of command content; per-host skill artifacts are generated by the export drivers from `commands/` entries. `enumerate_sources` still calls `_collect_skills` internally but returns an empty list because the directory no longer exists.
- The legacy adapter scripts (`export-common.py`, `export-cursor.py`, `export-codex.py`, `export-agy.py`) have been **removed**. The runtime drivers at `runtime/drivers/<target>/export.py` are the only current path.
- To regenerate the committed `exports/<host>/` mirror: `python3 -m z_harness_cli export --host <host> --out exports/<target> --force`. For agy specifically: `--host antigravity --out exports/agy`. The `--in-place` flag writes the host layout into the **current working directory** (for live workspace use) and does **not** populate the committed `exports/` mirror.
- `output_path_for` in `_export_utils.py` intentionally omits `agy` from `_TARGET_CONVENTIONS` — the agy exporter owns its own dual layout (`.agent/` + `prompts/`) and cannot be expressed as a single output path.
- Non-empty `warnings` from the runtime `export()` call are raised as `RuntimeError` by every adapter's `export_payload()` — the legacy hard-gate is preserved.
- When a skill ID collides with a command ID, Cursor and Codex append a `-skill` suffix to the export filename; agy flat prompts use a `skill-` prefix to avoid collisions.
- Codex consolidates all agents into a single `AGENTS.md`; no per-agent prompt files are emitted.
- Antigravity emits the most surfaces: workflows, rules, native skills, flat prompts, `agy-plugin.yaml`, `CAPABILITIES.md`, and `README.md`.
- `_ALWAYS_ON_AGENTS` in `runtime/drivers/_export_utils.py` hard-codes `implementer`, `reviewer`, `auditor`, `mr-reviewer`, `remote-runner`; all other agents get `model_decision` trigger. This constant is imported by the agy, windsurf, and kiro drivers.
- Antigravity workflow bodies have an ~12,000 character limit; several z-harness commands exceed it.
- `agy-plugin.yaml` is a z-harness convention manifest; Antigravity does not read it natively.
- pi is export-only: no adapter, no `HostDriver`, no `--host pi` CLI flag. Its export runs through `runtime/drivers/pi/export.py` via direct import. pi asset files (`CAPABILITIES.md`, `AGENTS.preamble.md`, `explore.md`, `extensions/`) live under `scripts/pi_assets/`.
- pi injects a prompt-defense block after `<!-- PROMPT_DEFENSE_MARKER -->` in exported agent files; falls back to after the heading line if no sentinel is found.
- pi has **no persona export**. Persona export runs only for cursor, codex, and agy.
- `inline_includes` accepts `base_dir` for API symmetry but never uses it — resolution is always relative to `repo_root` (preserved quirk from legacy `export-common.py`).
- `z_harness_cli/adapters/base.py` re-exports `ExportResult` with `__all__ = ['ExportResult']`; CLI-layer code and tests must import from `base`, not from `runtime.drivers._export_utils` directly.
- pi model mapping: `haiku` → `deepseek-v4-flash`, `sonnet`/`opus` → `deepseek-v4-pro`.
- `select_sources` and `resolve_strategy` are used by the export-only drivers (windsurf, kiro, cline, copilot) but not by the core four (cursor, codex, agy, pi) which enumerate all sources unconditionally.

## Examples

- `python3 -m z_harness_cli export --host cursor --out exports/cursor --force` — regenerates `exports/cursor/.cursor/rules/*.mdc`.
- `python3 -m z_harness_cli export --host codex --out exports/codex --force` — regenerates `exports/codex/prompts/*.md` and `exports/codex/AGENTS.md`.
- `python3 -m z_harness_cli export --host antigravity --out exports/agy --force` — regenerates workflows, rules, skills, prompts, manifest, `CAPABILITIES.md`, and `README.md` under `exports/agy/`.
- `python3 -m z_harness_cli export --host cursor --in-place` — writes `.cursor/rules/*.mdc` directly into the current working directory (live workspace use; does not update `exports/cursor/`).
- `python3 -c "from runtime.drivers.pi.export import export; from pathlib import Path; export(Path('.'), Path('exports/pi'))"` — regenerates the full `exports/pi/` tree.
