### Severity: minor (worth noting for future plans)

- [self-review] **Dependency ordering between amendment proposals is not addressed.** If two amendment proposals have a `**Depends on:**` link (e.g. T-REV-004 depends on T-REV-001), Phase 6.5 processes them in document order. The serial processing naturally handles most cases, but there's no explicit topological sort. In practice, dependencies between amendment proposals in the same review run are exceedingly rare, and the `/z-amend` invoked for each proposal handles its own dependency resolution internally.

- [self-review] **Re-run idempotency is not addressed.** If Phase 6.5 is interrupted after some amendments are applied, re-running `/z-review-all` rebuilds REVIEW-TASKS.md from the unchanged findings.md and re-applies the same amendments. `/z-amend` would encounter already-applied changes and either no-op or fail. A checkpoint marker (e.g. marking applied amendments in REVIEW-TASKS.md or writing a `.phase_6_5_done` sentinel) would make this robust. The TASK.md addresses rollback path (git) but not re-run safety.

- [self-review] **The slug for the inner `/z-amend` invocation is implicit.** Phase 6.5 says "Invoke `/z-amend --skip-user-gate "<amendment text>"` inline" and "Follow the `/z-amend` pipeline (Phase 0–8) for this slug." The context establishes that `this slug` = `$Z_HARNESS_SLUG`, but the argument-passing mechanics aren't fully specified. In practice, the orchestrator LLM running review-all would pass the slug as part of invoking the z-amend pipeline — this is a documentation clarity gap, not a behavior gap.

- [self-review] **The policy auto-amends all three severities (blocker, major, minor) equally.** The TASK.md rationale (cross-LLM review already validated them) is sound. However, a user with a preference for manual review of minor spec changes has no opt-out per-run — they can only roll back via git after the fact. The TASK.md acknowledges this: "The user CAN still opt out after the fact via git." A future iteration could add a per-severity opt-out config key (e.g. `Z_HARNESS_AUTO_AMEND_SEVERITY=blocker,major`).
