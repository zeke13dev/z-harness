# PLAN: doc-memories

## Goal

Add a curated-memories layer to the z-harness two-tier docs system so that orchestrators can retrieve institutional context — anti-patterns, abandoned paths, incident lessons, decision rationale — alongside the existing concept→file:line pointers. Backward-compatible.

## Approved decisions

| ID | Decision | Rationale |
|----|----------|-----------|
| D1 | Memory schema = Codex shape + optional `expires` | Strict-prefix `source` is ripgrep-parseable; `expires` is cheap author-set decay metadata distinct from D7's bulk staleness flag. |
| D2 | Hybrid tag taxonomy (controlled chips + free-form) | Pre-enumerated tags are guesses; free-form lets domain taxonomies grow. Dedup pass in doc-updater handles drift without auto-merging. |
| D3 | MEMORIES-FLAT.md line = `[<slug>] [<TYPE> <DATE>] [<source>] <text> (tags: ...)` | Self-contained per line — no `rg -B` context needed. Source in the line preserves provenance (Gemini's amendment). |
| D4 | doc-fetcher reuses `query` + optional `tags` | Tags constrained to D2's taxonomy → mitigates LLM tag hallucination. Reusing `query` keeps the common case backward-compatible. |
| D5 | /z-suggest-memory uses `concept_hints` + "create new concept" handoff | Hints come from `/z-debug` PROBLEM.md and `/z-improve` touched files. "Create new concept" hands off to `/z-init-docs --scope <slug>` rather than allowing a "GLOBAL" junk drawer. |
| D6 | Ripgrep soft dependency with substring fallback | Per BRAINSTORM. One-line PATH check. |
| D7 | 18-month staleness threshold via `Z_HARNESS_MEMORY_STALE_DAYS` (default 547) | Surfaces in /z-maintain-docs Phase 3; never auto-deletes. |
| D8 | MEMORIES-FLAT.md regenerated by /z-init-docs, /z-maintain-docs, /z-suggest-memory | Full regen every time; file is small. |
| D9 | LLM tier authoritative; doc-updater extracts to human tier | Single source of truth. Human edits to markdown not round-tripped. |
| D10 | /z-suggest-memory return shape: STATUS/CONCEPT/MEMORIES_WRITTEN/WROTE | Caller logs but does not block on it. |
| D11 | Fixture-based tests; no end-to-end against real docs/llm/ | Per ship-blind user decision. Validation in target repo post-merge. |
| D12 | 200-char text limit, enforced at write | Codex schema. Hard rejection, no silent truncation. |
| D13 | Memories are mutable (not append-only) | Per user choice. /z-suggest-memory supports append (default), edit, delete. |

## Non-goals

- Embedding / vector search.
- Dedicated `docs-search` agent.
- Deprecating `invariants` / `gotchas` short-string fields.
- Bootstrapping z-harness's own `docs/llm/` (separate effort).
- `/z-plan` retro hook for abandoned-path memories (kept /z-plan scope contained).
- Auto-merging tag collisions (humans decide via /z-maintain-docs review).
- Round-tripping human-edited memories from `docs/human/<slug>.md` back into LLM tier.

## Approved shortcuts

**None.** All decisions accepted the robust long-lasting option.

## Ordered phases

1. **Schema + line format (foundation).** Update `agents/doc-updater.md` to add `memories[]` to the LLM-tier JSON contract and the `## Memories` section to the human-tier contract. Specify the MEMORIES-FLAT.md line format in a shared SPEC location everyone references.
2. **MEMORIES-FLAT.md generation logic.** Create `scripts/regenerate-memories-flat.py` (signature in SPEC). Extend `skills/z-init-docs/SKILL.md` (initial empty file with header) and `skills/z-maintain-docs/SKILL.md` (Phase 4.5 regenerator) — both shell out to the helper.
3. **doc-fetcher second-phase ripgrep.** Update `agents/doc-fetcher.md` with the new step 2.5, the `tags` optional input, the substring fallback path, and the memories synthesis subsection.
4. **/z-suggest-memory skill + command.** Create `skills/z-suggest-memory/SKILL.md` and `commands/z-suggest-memory.md`. Implements the authoring flow (resolve target, collect, validate, write, regen, refresh human).
5. **Retro hooks.** Update `skills/z-debug/SKILL.md` Phase 7 and `skills/z-improve/SKILL.md` Phase 7 to invoke `/z-suggest-memory` mandatorily. Update PROBLEM.md template to include `Relevant concepts:` line.
6. **Tag dedup pass in doc-updater.** Add step 3.5 + `TAG_COLLISIONS` return block; surface in /z-maintain-docs Phase 3.
7. **Stale-memory flagging in /z-maintain-docs.** Phase 3 surfaces memories where `expires < today` or `date < today - Z_HARNESS_MEMORY_STALE_DAYS`.
8. **Tests + fixtures.** Create `z-harness/doc-memories/test-fixtures/` with synthetic INDEX.json, per-concept JSONs, and MEMORIES-FLAT.md. Five unit-style fixture tests (D11).
9. **README + cross-reference.** README.md skills table; cross-link in `agents/doc-fetcher.md` and `agents/doc-updater.md` to /z-suggest-memory.

Phases 1–3 are sequential (each depends on the prior). Phases 4–9 can largely parallelize after phase 3 lands.

## DRY / KISS / SOLID

- **DRY.** MEMORIES-FLAT.md regen logic lives once (Python helper invoked by /z-init-docs, /z-maintain-docs, and /z-suggest-memory). Memory schema defined once in SPEC.md; all three skills reference the same shape. Tag taxonomy lives once in `docs/llm/TAGS.txt` (created on first /z-suggest-memory call if absent, seeded with controlled set).
- **KISS.** No embedding store, no dedicated agent, no append-only ledger machinery. Schema is six fields. Line format is one regex away from JSON. Ripgrep is a soft dep — one PATH check, one fallback path.
- **SOLID.** doc-fetcher remains the single retrieval surface (no `docs-search` split). doc-updater stays a *structural* extractor — never invents memories. /z-suggest-memory is the *only* authoring path (single-responsibility). /z-debug and /z-improve depend on /z-suggest-memory's interface, not its internals.
